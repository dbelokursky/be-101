# Шпаргалка: Kafka

## Словарь

| Термин | Смысл |
|---|---|
| Topic | Именованный лог событий (`домен.факт`) |
| Partition | Параллельный лог; единица порядка и масштаба |
| Ключ | Хэш ключа → партиция; события одной сущности — по порядку |
| Offset | Номер события; закладка читателя, хранится на группу |
| Consumer group | Инстансы делят партиции; событие — ровно одному инстансу группы |
| Retention | Сколько topic хранит события (можно перечитать) |
| Lag | Отставание группы от хвоста лога — главная метрика консюмера |
| DLT | Кладбище событий после N неудачных обработок |

## Продюсер

```java
kafkaTemplate.send("orders.created", String.valueOf(orderId), event);
```

| Настройка | Эффект |
|---|---|
| `acks=all` | Подтверждение репликами — норма для доменных событий |
| `enable.idempotence=true` | Ретраи не плодят дубли записи |
| ключ = orderId | Порядок событий заказа |

**Dual-write**: БД + Kafka в одном методе = рассинхрон. Лечение — **outbox**: событие в таблицу в той же транзакции, релей публикует.

## Консюмер

```java
@KafkaListener(topics = "orders.created", groupId = "mail-service")
```

- Коммит offset'а **после** обработки: потерять нельзя, дубль — можно (at-least-once)
- Обработчик обязан быть идемпотентным:
  - `UPDATE ... SET status='X' WHERE status<>'X'` — естественно идемпотентно
  - `processed_events(eventId)` в одной транзакции с эффектом
  - версии событий против «v1 пришла после v2»
- Ядовитое сообщение → `@RetryableTopic` + `@DltHandler`, алерт на глубину DLT
- Медленная обработка (> `max.poll.interval.ms`) → выпадение из группы → ребалансы

## Семантики

| Семантика | Достигается |
|---|---|
| At-most-once | Коммит до обработки (теряем) |
| At-least-once | Коммит после обработки (дублируем доставку) |
| Effectively-once | At-least-once **+ идемпотентный обработчик** |

## Правила выживания

- Имя topic'а — контракт: `orders.created`, не `events`
- Уровень надёжности = цена потери события (клики ≠ платежи)
- Outbox для обязательных событий; версиями — порядок; сагами — длинные процессы
