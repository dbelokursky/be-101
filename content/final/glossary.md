# Глоссарий курса

Все термины курса в одном месте — по модулям, внутри в алфавите. Ищите через Ctrl+F / ⌘F.

## Модуль 1. Spring Boot с нуля

| Термин | Определение |
|---|---|
| **DTO** (Data Transfer Object) | Класс, описывающий формат данных на границе API: стабилизирует контракт, не пускает внутренности наружу |
| **DI** (Dependency Injection) | Механика Spring: фреймворк сам подставляет реализации в поля/конструкторы по интерфейсам |
| **Entity** | Java-класс, отображённый на таблицу БД (`@Entity`); «таблица, живущая как объект» |
| **HTTP** | Протокол диалога клиента и сервера: метод + путь + заголовки + тело → статус + тело |
| **JVM** | Виртуальная машина Java — «движок», на котором запускаются Java-программы |
| **Lombok** | Генератор бойлерплейта на этапе компиляции: `@Getter`, `@Builder`, `@Data` |
| **MapStruct** | Генератор мапперов между объектами (entity ↔ DTO) на этапе компиляции |
| **Optional** | Обёртка «значения может не быть»: честный null без NullPointerException-рулетки |
| **Порт** | «Окно» с номером, через которое процесс принимает соединения; дефолт Spring Boot — 8080 |
| **Профили** (dev/prod) | Наборы настроек для окружений: один код, разные базы/уровни логов |
| **Репозиторий** | Слой доступа к данным: `JpaRepository`, SQL по имени метода |
| **Сервисный слой** | Бизнес-логика: правила «что можно и почём», не знает про HTTP |
| **Статус-код** | Трёхзначный код ответа: 2xx успех, 4xx вина клиента, 5xx вина сервера |
| **Транзакция** (@Transactional) | «Всё или ничего»: упало на середине — изменения откатываются |

## Модуль 2. Проектирование API

| Термин | Определение |
|---|---|
| **API-First** | Подход «сначала контракт»: спека OpenAPI → ревью → код и клиенты генерятся из неё |
| **Backward compatibility** | Обратная совместимость: старые клиенты продолжают работать после изменения |
| **Breaking change** | Изменение, ломающее клиентов (удалить/переименовать поле, сменить тип) — только через версию |
| **GraphQL** | Стиль API, где клиент сам заказывает поля одним запросом; схема = контракт |
| **Идемпотентность** | Повтор запроса не меняет результат сверх первого раза (GET/PUT/DELETE — да, POST — нет) |
| **Мок-сервер** | Фейковый API, отвечающий по спеке: фронт работает до готовности бэкенда |
| **OpenAPI** | Стандарт машиночитаемого описания REST API в YAML/JSON |
| **Problem Details** | RFC 7807: единый формат ошибок JSON — машина по `status`+`code`, человек по `title/detail` |
| **$ref** | Ссылка на переиспользуемую схему в `components/schemas` спеки |
| **Deprecation / Sunset** | Заголовки объявления устаревания и даты выключения версии API |
| **Схема (GraphQL)** | Описание типов и полей, которые сервер умеет отдавать (`schema.graphqls`) |
| **Swagger UI** | Интерактивная документация из OpenAPI: читать и пробовать запросы |

## Модуль 3. Данные

| Термин | Определение |
|---|---|
| **Dirty checking** | Hibernate сам сравнивает entity с снимком и генерирует UPDATE при коммите |
| **DLT** | Топик для «необрабатываемых» сообщений (подробнее в модуле 4) |
| **FK** (внешний ключ) | Колонка, указывающая на PK другой таблицы; база охраняет связь |
| **Full scan** | Поиск полным перебором строк без индекса — «внезапные» тормозы на проде |
| **Индекс** | Отсортированная структура по колонке: быстрый поиск ценой замедления записи |
| **JOIN** | Соединение таблиц по условию связи в одном SQL-запросе |
| **Lazy / EAGER** | Отложенная/жадная загрузка связи: LAZY — при первом обращении, EAGER — сразу всегда |
| **LazyInitializationException** | Обращение к ленивой связи вне открытой сессии/транзакции |
| **N+1** | 1 запрос за списком + N за связями каждого элемента |
| **Offset / Pageable** | Пагинация в SQL (LIMIT/OFFSET) вместо вытаскивания всего в память |
| **@Version** | Оптимистичная блокировка: конфликт ловится при UPDATE → исключение и повтор |
| **Outbox** | Паттерн атомарной публикации событий из БД-транзакции (подробнее в модуле 4) |
| **PK** (первичный ключ) | Значение, однозначно идентифицирующее строку таблицы |
| **Testcontainers** | Настоящие СУБД (и не только) в Docker на время интеграционных тестов |
| **Уровни изоляции** | READ COMMITTED / REPEATABLE READ / SERIALIZABLE — что видят параллельные транзакции |
| **Changeset** | Атомарный шаг миграции Liquibase; применённый — неизменен (чек-сумма) |

## Модуль 4. Kafka вглубь

| Термин | Определение |
|---|---|
| **At-least-once** | «Хотя бы один раз»: повторы доставки возможны → обработчик идемпотентен |
| **Брокер** | Сервер Kafka: принимает, хранит, раздаёт события |
| **DLT** (Dead Letter Topic) | Топик-кладбище событий, не обработанных за N попыток; алерт на глубину |
| **Консюмер** | Подписчик: читает топик в своём темпе, группа делит партиции |
| **Ключ сообщения** | Маршрутизатор в партицию; события одного ключа — строго по порядку |
| **Лаг** (lag) | Отставание группы от хвоста лога — главная метрика консюмера |
| **Offset** | Номер события в партиции; закладка группы, хранится в Kafka |
| **Outbox** | Таблица-«исходящий ящик»: событие атомарно с бизнес-записью, релей публикует |
| **Партиция** | Параллельный лог; единица порядка и масштабирования |
| **Продюсер** | Издатель событий: сериализация → партиция по ключу → батч → acks |
| **Rebalance** | Перераспределение партиций между инстансами группы при смене состава |
| **Retention** | Время хранения событий в топике: можно перечитать |
| **Сага** | Цепочка локальных транзакций с компенсациями для длинных процессов |
| **Топик** | Именованный лог событий; именование `домен.факт` |
| **TraceId** | Идентификатор, связывающий все логи и span'ы одного запроса (подробнее в модуле 5) |

## Модуль 5. Наблюдаемость

| Термин | Определение |
|---|---|
| **Burn rate** | Темп сгорания бюджета ошибок SLO — основа «умных» алертов |
| **Gauge** | Метрика «сколько сейчас»: снимается в момент опроса |
| **Counter** | Метрика «сколько раз»: только растёт |
| **Золотые сигналы** | Traffic / Latency (p99) / Errors / Saturation — основа дашборда дежурного |
| **Кардинальность** | Число уникальных значений тега; уникальные id в тегах убивают Prometheus |
| **MDC** | Поток-локальный контекст логгера: кладёшь traceId — он в каждой строке |
| **Micrometer** | «SLF4J для метрик»: один API, много бэкендов |
| **Перцентиль** (p99) | Значение, ниже которого лежит 99% измерений; хвост важнее среднего |
| **Постмортем** | Разбор инцидента без поиска виноватых: что/почему/действия |
| **Runbook** | Инструкция «что делать» к алерту: первый шаг дежурного |
| **SLO** | Договор о допустимом несовершенстве: «99.9% успешны за 30 дней» |
| **Span** | Отрезок работы в трейсе: контроллер → SQL → внешний вызов |
| **Трейс** | Путь запроса через сервисы, связанный одним traceId |
| **p50 / p95 / p99** | Перцентили задержек: медиана / «почти все» / «хвост» |
