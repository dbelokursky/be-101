# Ревью контракта отмены заказа

Анна оформила заказ `42` 15 января в `12:00:00Z`. Команда хочет дать владельцу 24 часа на отмену. При отмене заказ переходит в `CANCELLED`, бонусы возвращаются один раз. Клиент иногда повторяет запрос после таймаута.

Фрагмент OpenAPI уже описывает путь, токен и ключ повтора. На ревью надо договориться о граничном времени и о повторном вызове.

```yaml
paths:
  /api/orders/{orderId}/cancel:
    post:
      summary: Отменить заказ
      security:
        - bearerAuth: []
      parameters:
        - name: orderId
          in: path
          required: true
          schema: { type: integer }
        - name: Idempotency-Key
          in: header
          required: true
          schema: { type: string, minLength: 1 }
      responses:
        '204':
          description: Отмена принята
        '401':
          description: Нужен действительный токен
        '403':
          description: Отмена запрещена этому пользователю
        '404':
          description: Заказ не найден
        '409':
          description: Операция конфликтует с состоянием заказа
```

```case
title: "Согласуй правила и примеры для клиента"
task: >
  Запиши ожидаемые статусы и, где нужен отказ, машинные коды.
  Что ответит API в 11:59:59Z, 12:00:00Z и 12:00:01Z на следующий день после создания?
  Как ответить на повтор успешного запроса с тем же ключом и на новую попытку с другим ключом?
  Аналитик формулирует правила перехода состояния.
  Фронтендер указывает, что покажет при успехе, отказе и таймауте.
  QA описывает проверки времени, собственника заказа и числа возвратов.
placeholder: "Правило и граница времени\nОжидаемые статусы и коды\nЧто делает клиент\nЧто проверяет QA"
reference: |
  ## Правило времени и повтора

  Срок открыт, пока серверное время строго меньше времени создания заказа плюс 24 часа. Ровно на границе срок уже истёк.

  Сервис проверяет аутентификацию и право владения. Затем ищет успешный результат по ключу в рамках пользователя и заказа. Найденный результат возвращается повторно даже после истечения срока. При новом ключе сервис проверяет состояние заказа и оставшееся время.

  | Запрос на 16 января | Ответ |
  | --- | --- |
  | Первый вызов Анны в `11:59:59Z` | `204`. Заказ переходит в `CANCELLED`, бонусы возвращаются один раз |
  | Первый вызов Анны в `12:00:00Z` | `409 CANCELLATION_WINDOW_EXPIRED` |
  | Первый вызов Анны в `12:00:01Z` | `409 CANCELLATION_WINDOW_EXPIRED` |
  | Повтор успешного вызова с тем же ключом | `204`. Сохраняется единственный возврат |
  | Новый ключ у уже отменённого заказа | `409 ORDER_ALREADY_CANCELLED` |
  | Запрос без действительного токена | `401` с `WWW-Authenticate: Bearer` |
  | Запрос Бориса к заказу Анны | `403` |

  Для проверки границы каждый первый вызов в таблице выполняется на новом исходном экземпляре заказа.

  ## Уточнение ответов в OpenAPI

  Задай `400` для отсутствующего обязательного заголовка. Для `204` укажи, что это успешная отмена или повтор её результата без тела. У `409` опиши тело с `Content-Type: application/problem+json` и двумя возможными кодами.

      '409':
        description: Срок истёк или заказ уже отменён при новой попытке
        content:
          application/problem+json:
            schema:
              type: object
              required: [title, status, code]
              properties:
                title: { type: string }
                status: { type: integer, enum: [409] }
                code:
                  type: string
                  enum: [CANCELLATION_WINDOW_EXPIRED, ORDER_ALREADY_CANCELLED]

  ## Как этим пользуется команда

  - Аналитик фиксирует переход из `NEW` в `CANCELLED` и предел в 24 часа. Успешный повтор относится к первой операции.
  - Фронтендер на `204` показывает отменённый заказ. При `409` выбирает действие по `code`. После таймаута проверяет состояние заказа или повторяет отмену с тем же ключом.
  - QA проверяет три момента времени на исходном заказе, отказ другому покупателю, успешный повтор и попытку с новым ключом. После двух одинаковых запросов ожидает один возврат бонусов.
```

## Проверь контракт запросами

В учебном API есть заказ `42`. Кнопка «Сбросить заказ» возвращает его в `NEW` и очищает журнал возвратов. Переключатель времени передаёт показание учебных часов в заголовке `X-BE101-Time`.

1. Сбрось заказ. От имени владельца отправь `POST /cancel` в `11:59:59Z` и запиши результат.
2. Переведи время на `12:00:01Z` и повтори запрос с тем же `Idempotency-Key`. Затем проверь статус заказа и число строк в журнале возвратов.
3. Замени ключ и отправь запрос ещё раз. Сверь код ошибки с контрактом и снова проверь журнал.
4. Сбрось заказ и проверь первый запрос ровно в `12:00:00Z`. Повтори проверку прав от имени другого покупателя.

На сайте запросы видны в DevTools → Network. При открытии курса с диска упражнение выполняется в локальной модели до перезагрузки вкладки.
