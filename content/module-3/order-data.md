# Отмена заказа в данных

По [контракту отмены](#/m2-order-cancellation-review) заказ `42` должен перейти в `CANCELLED`, а покупателю полагается один возврат бонусов. Сверь обе части правила по данным учебного сервиса.

## Срез после отмены

Срез сделан 16 января в `11:59:53Z`. В `orders` строку определяет поле `id`. В журнале бонусов поле `order_id` связывает операцию с заказом.

**Таблица `orders`**

| id | status | cancelled_at |
| --- | --- | --- |
| 42 | CANCELLED | 2026-01-16T11:59:52.180Z |
| 77 | CANCELLED | 2026-01-16T10:12:04.600Z |

**Таблица `bonus_transactions`**

| id | order_id | reason | amount | created_at |
| --- | --- | --- | --- | --- |
| refund-77 | 77 | ORDER_CANCELLED | +80 | 2026-01-16T10:12:04.600Z |
| adjustment-42 | 42 | SUPPORT_ADJUSTMENT | +15 | 2026-01-16T10:30:00Z |
| refund-42 | 42 | ORDER_CANCELLED | +120 | 2026-01-16T11:59:52.180Z |

Положительная сумма означает зачисление. Чтобы проверить именно возврат при отмене, отбери строки по заказу и причине операции.

```sql
SELECT id, status, cancelled_at
FROM orders
WHERE id = 42;

SELECT id, amount, created_at
FROM bonus_transactions
WHERE order_id = 42 AND reason = 'ORDER_CANCELLED';
```

## Два параллельных запроса

Для отдельной проверки QA восстановил исходное состояние заказа `42`. Анна отправила два запроса из разных вкладок с действительным токеном. Оба пришли до истечения 24 часов.

| Время 16 января | Запрос | Idempotency-Key |
| --- | --- | --- |
| 11:59:52.010Z | `POST /api/orders/42/cancel` | test-tab-a |
| 11:59:52.015Z | `POST /api/orders/42/cancel` | test-tab-b |

```case
title: "Проверь состояние заказа и число возвратов"
task: >
  По срезу назови статус заказа 42 и укажи запись, которая подтверждает возврат.
  Для параллельного прогона сформулируй правило, которое должно выполняться при любой очередности запросов.
  Назови ожидаемые ответы API и то, что нужно проверить в обеих таблицах после завершения запросов.
placeholder: "Статус и строка возврата\nПравило для двух вкладок\nОжидаемые ответы\nПроверка в БД"
reference: |
  Заказ `42` отменён. Возврат — строка `refund-42` с `order_id = 42`, причиной `ORDER_CANCELLED` и суммой `+120`. Корректировка поддержки относится к другой операции. Возврат по заказу `77` проверяется отдельно.

  В параллельном прогоне кто-то первым переводит заказ из `NEW` в `CANCELLED` и получает `204`. Второй запрос с другим ключом получает `409 ORDER_ALREADY_CANCELLED`. Кто именно получит `204`, зависит от очередности выполнения.

  Инвариант для любого порядка — один переход в `CANCELLED` и одна строка возврата с суммой `+120`. Проверка состояния и запись возврата должны быть атомарны. Например, сервис блокирует строку заказа в транзакции и повторно проверяет статус после получения блокировки. Параллельный запрос увидит сохранённую отмену перед тем, как попытаться начислить бонусы.

  Срез подтверждает итог операции. Два конкурентных запроса в тесте проверяют, сохранится ли тот же итог при гонке.
```
