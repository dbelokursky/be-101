# Урок 3. Интеграционные тесты: Spring и MockMvc

Юнит проверяет правило. Но заказы падают не на правилах, а на швах: JSON не тот, колонка переименована, валидация не включилась. Интеграционный тест поднимает **настоящие слои вместе** — вы это уже видели в лабах 2 и 5; теперь разложим по полочкам.

## @SpringBootTest: поднять приложение

```java
@SpringBootTest
@AutoConfigureMockMvc
@Transactional
class TaskApiTest {

    @Autowired
    private MockMvc mockMvc;

    @Autowired
    private TaskRepository taskRepository;
}
```

- `@SpringBootTest` — поднимает весь контекст: контроллеры, сервисы, репозитории, конфиг
- `@AutoConfigureMockMvc` — даёт `MockMvc`: вызовы HTTP **без сети** — запрос идёт через диспетчер прямо в контроллер
- `@Transactional` на тест-классе — каждый тест откатывается: база чистая, тесты независимы

В Boot 4 не забудьте стартер `spring-boot-starter-webmvc-test` — MockMvc живёт в нём (модульные тесты разделили, как это было с Liquibase и Kafka).

## MockMvc: HTTP по-честному, сеть по-дешёвому

```java
@Test
void createTask_returns201AndLocation() throws Exception {
    mockMvc.perform(post("/api/projects/7/tasks")
                    .contentType(MediaType.APPLICATION_JSON)
                    .content("""
                        {"title":"Купить молоко"}
                        """))
            .andExpect(status().isCreated())
            .andExpect(header().string("Location", containsString("/api/tasks/")))
            .andExpect(jsonPath("$.done").value(false));

    assertThat(taskRepository.count()).isEqualTo(1);   // и в базе правда лежит
}
```

Что здесь честного: JSON-сериализация, валидация (`@Valid`), маппинги, статусы, заголовки, INSERT в базу. Нечестного — только сеть и порт: MockMvc вызывает DispatcherServlet напрямую.

Проверка содержимого ответа — `jsonPath` (`$.done`), типов и заголовков — как в курсе с первого квиза про статусы.

## База в тестах: H2 и @Transactional

Схема в тестах та же, что в рантайме: **Liquibase накатывает миграции** при старте контекста (вы это делали в лабе 5). H2 in-memory — быстро и без Docker; оговорки диалекта — в уроке 4.

`@Transactional` на тесте оборачивает его в транзакцию с откатом: вставки не протекают в соседние тесты. Тонкость: после отката данные исчезают — если тест проверяет «коммитится ли», откат мешает; для таких случаев тест без `@Transactional` + ручная чистка (`@BeforeEach deleteAll()`).

## Срезы: когда весь контекст не нужен

| Аннотация | Поднимает | Для |
|---|---|---|
| `@SpringBootTest` | всё | сквозные проверки API |
| `@DataJpaTest` | только JPA+базу | репозитории и запросы |
| `@SpringBootTest` + `MockMvc` | всё кроме сети | HTTP-границы |

`@DataJpaTest` — срез: контекст в разы меньше и быстрее; для «правильно ли генерируется SQL фильтра» полный контекст не нужен.

## Стоимость контекста и кэш

Контекст стартует секунды. Spring кэширует его между тестами **одинаковой конфигурации**: меняете `@MockBean`, свойства или профили в одном тесте — получите второй контекст. Правило: не плодить миксы конфигураций без нужды; общий дефолт — быстро, каждый «особый» тест замедляет набор.

`@MockBean` (в 3.4+ — `@MockitoBean`) — подмена бина в поднятом контексте: «внешний шлюз в тестах платежей отвечает ошибкой». Мощно для сценариев сбоев, но каждый такой тест = новый контекст.

## Что проверять интеграционно

- Контракт эндпоинтов: статусы, заголовки, JSON — то, чем API отвечает потребителю
- Валидацию: невалидный JSON → 400; пустое поле → 400 с указанием
- Бизнес-цепочку: POST создал → GET видит → DELETE убрал
- Ошибки: 404 на несуществующее, 409 на конфликт

> **🔧 QA:** MockMvc-тесты — это ваши API-автотесты, живущие рядом с кодом: падение краснит билд автора, а не отдельную джобу. Пограничные кейсы из ваших чек-листов (400/404/409) — ровно то, что сюда ложится.

## Итог

- `@SpringBootTest` + `@AutoConfigureMockMvc` + `@Transactional`: всё по-настоящему, кроме сети
- MockMvc: статусы/заголовки/jsonPath;assert на базе закрывает «действительно сохранилось»
- Схему в тестах создаёт Liquibase; H2 для скорости, Testcontainers для честности (урок 4)
- Срезы (`@DataJpaTest`) для репозиториев; контекст кэшируется — не плодите вариации
- Проверяйте контракт эндпоинта и цепочку, а не каждую строчку
