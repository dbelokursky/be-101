# Урок 4. Логи и корреляция

Логи — самый старый инструмент и до сих пор главный на разборе инцидентов. Разница между «логами» и «полезными логами» — структура и корреляция. Урок — как писать логи, по которым расследование занимает минуты.

## Структурированные логи: JSON вместо прозы

```json
{"timestamp":"2026-11-12T10:15:03Z","level":"INFO","logger":"be101.orders.OrderService",
 "message":"order created","orderId":42,"customer":"ann","amount":5990,"traceId":"a4f9c2..."}
```

Против `10:15:03 INFO Заказ 42 создан для ann на 5990`. Человек прочитает оба; машина (Loki, ELK) — только первый: фильтры `orderId=42 AND level=ERROR`, графики по полям, алерты по подсчётам. В Spring Boot: logback-encoder + `logging.pattern` в JSON — поля из MDC и аргументы автоматически.

Поля — змеёй/верблюдом, но одинаково везде; `message` — короткий факт, детали — полями.

## Уровни: дисциплина, не настроение

| Уровень | Смысл | Пример |
|---|---|---|
| ERROR | Нужен человек: функциональность потеряна | Не сохранился заказ |
| WARN | Странно, но обработано: присмотритесь | Ретрай внешнего вызова, DLT+1 |
| INFO | Значимые факты жизни | Заказ создан, конфигурация применена |
| DEBUG | Детали для отладки | Параметры SQL, решение бизнес-правила |

Антипаттерн — ERROR-шум: ожидаемый 404 или чужой кривой токен сыпятся ERROR'ами → на алерты перестают смотреть → настоящий ERROR теряется. ERROR — не «мне стало страшно», а «дежурному встать».

## MDC и traceId: нитка через весь запрос

**MDC** (Mapped Diagnostic Context) — поток-локальная карта «поле → значение», автоматически подмешиваемая в каждую строку лога этого потока:

```java
MDC.put("traceId", UUID.randomUUID().toString());
try {
    log.info("order created");      // в логе будет traceId автоматически
} finally {
    MDC.remove("traceId");
}
```

В распределённой системе traceId приходит **снаружи** (HTTP-заголовок от фронта/шлюза) или создаётся на входе — фильтр/интерцептор. Дальше он путешествует:

- в HTTP-ответе (заголовок) — поддержка просит его у пользователя при тикете
- в исходящих вызовах — заголовком дальше
- **в Kafka** — заголовком сообщения: консюмер кладёт в MDC перед обработкой

```java
@KafkaListener(topics = "orders.created")
public void on(OrderCreatedEvent e, @Header("traceId") String traceId) {
    MDC.put("traceId", traceId);
    try { process(e); } finally { MDC.remove("traceId"); }
}
```

Без этой ниточки «асинхронный инцидент» = восемь несвязанных логов в восьми сервисах; с ней — одна история с общим traceId.

## Что логировать (и что — никогда)

Логировать: факты смены состояния, решения бизнес-правил (DEBUG), внешние вызовы (кто/зачем/сколько), ошибки с контекстом.

**Никогда**:

- секреты: пароли, токены, номера карт (даже частично — регуляторы не шутят)
- персональные данные сверх необходимого (email — ок в контексте заказа по легальным основаниям; паспорт — нет)
- тела целиком «на всякий случай» (объём + утечки + GDPR-стиль проблемы)
- в цикле на миллион итераций (лог-шторм топит и диск, и агрегатор)

## Логи vs метрики vs трейсы: кто за что

Не дублируйте: счётчик не нужен там, где достаточно метрики; стек всей цепочки — работа трейса. Лог — событие с контекстом, которое объяснит «почему», когда метрика скажет «что». Практическое правило: по каждому ERROR в логе должно быть можно построить график частоты, а по каждому графику 5xx — найти примеры в логах.

> **🔧 QA:** тестируйте логи как контракт: бизнес-ошибка → WARN/ERROR с кодом, в каждой строке traceId, секреты не встречаются (простой grep по тестовым паролям). «Логи есть» ≠ «по ним можно расследовать».

## Итог

- Структурированный JSON-лог: поля вместо прозы, машина и человек читают одно и то же
- Уровни — дисциплина: ERROR = «нужен человек»; шум убивает алерты
- MDC + traceId: нитка от фронта через сервисы и Kafka до последнего обработчика
- Секреты и лишние персональные данные — никогда; миллион строк в цикле — тоже
- Логи объясняют «почему», метрики — «что», трейсы — «где»: не дублировать

Последний урок модуля — дашборды и алерты: как из метрик сделать систему, которая зовёт людей вовремя, а не ночью по пустякам.
