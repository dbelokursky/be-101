# Лаба 8. Юнит-тесты (после урока «JUnit и Mockito»)

Первая лаба, где вы пишете **не код, а тесты**. Сервис готов и менять его нельзя:
ваша задача — описать его поведение юнит-тестами так, чтобы покрытие стало 80%+.

Приёмник необычный: не тест-кейсы, а **правило JaCoCo** — `mvn test` падает,
пока строки `DiscountService` не покрыты тестами на 80% и больше.

## Как начать

```bash
git checkout lab-8
mvn test
```

Сейчас сборка падает на правиле покрытия (покрыто 0%). Откройте два файла:

| Файл | Роль |
|---|---|
| `src/main/.../DiscountService.java` | Готовый: правила скидки, менять нельзя |
| `src/test/.../DiscountServiceTest.java` | **TODO**: ваши тесты (кейсы перечислены) |

## Что важно

- Каждый кейс — свой `@Test` с именем `правило_при_условии_результат`
- Деньги сравнивайте `isEqualByComparingTo`, а не `isEqualTo` (урок 2!)
- Границы обязательны: 5000 — это уже 5%, 4999.99 — ещё нет; ноль и минус — исключение
- Моки не нужны: у сервиса нет соседей — и это правильно спроектированный юнит

## Как смотреть покрытие

После `mvn test` откройте `target/site/jacoco/index.html` — жёлтые строки
не покрыты. Доведите до 80%+ (по-хорошему — до 100%: сервис маленький).

## Сверка с решением

```bash
git stash && git checkout lab-8-solution
mvn test          # BUILD SUCCESS, покрытие 100%
git checkout lab-8 && git stash pop
```
