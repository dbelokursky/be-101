Ситуация: в прод поехала фича задач, и мониторинг принёс два инцидента.
Приёмные тесты (`AcceptorApiTest`) уже показывают их красным — названия
тестов с `INCIDENT` подскажут, что именно сломано.

Ваша работа, как в настоящем фикс-PR: (1) понять по тестам, что случилось;
(2) починить контроллер; (3) **закрыть баги регрессией** — добавить свои тесты.

## Как начать

```bash
git checkout lab-9
mvn test
```

Упавшие тесты — карта инцидентов:

| Красный тест | Инцидент | Где чинить |
|---|---|---|
| `createTask_INCIDENT_returns201` | Создание отвечает не 201 | `TaskController.create` — статус успешного создания (урок 1 модуля 1) |
| `createTaskWithBlankTitle_INCIDENT_returns400` | Пустой title проходит | Валидация тела запроса (урок 4 модуля 1) |

**Правила игры:** менять можно только `TaskController.java` и `TaskApiStudentTest.java`.
DTO с `@NotBlank` уже готов — аннотация валидации на контроллере «потерялась».
