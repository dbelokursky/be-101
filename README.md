## Что нужно описать

Требования к контракту (продакт-голосом):

> «Хочу бронировать переговорки. При создании укажу комнату и время начала/конца.
> Если слот занят — скажите честно, я покажу пользователю понятную ошибку.
> Хочу видеть список своих броней и отменять бронь. Кто забронировал — важно.»

Формально:

1. **`POST /api/bookings`** — создать бронь
   - тело обязательно, схема `CreateBookingRequest`: `roomId`, `startsAt`, `endsAt` — все required
   - ответы: `201` (создана), `400` (валидация), **`409`** (слот занят)
   - у `409` должен быть `example` с машинным `code` (например `SLOT_TAKEN`) —
     фронтендер ветвится по коду, а не по тексту
2. **`GET /api/bookings`** — список броней (200)
3. **`DELETE /api/bookings/{id}`** — отмена, `204` без тела (и `404`)
4. **Схемы в components.schemas**:
   - `CreateBookingRequest` — required: `roomId`, `startsAt`, `endsAt`
   - `Booking` — поля `id`, `roomId`, `startsAt`, `endsAt`, `status` (ACTIVE/CANCELLED),
     `bookedBy`; required: первые пять

Подсказки: форматы дат — `format: date-time`; статус можно описать строкой с
`enum: [ACTIVE, CANCELLED]`; GUID комнаты — строка.
