# Лаба 10. Выпускной проект Spring — эталон

В [заготовке](https://github.com/dbelokursky/be-101/blob/lab-10/README.md) `OrderService.create` отправляет событие и увеличивает счётчик до коммита БД. Откат убирает заказ из БД, а сообщение и счётчик уже успевают измениться. Если асинхронная отправка завершается ошибкой, заказ может сохраниться без события. Оба случая разобраны в [уроке про dual-write](https://dbelokursky.github.io/be-101/#/m4-lesson-03).

## Как проходит создание заказа

```text
POST /api/orders
  ├─ транзакция БД → orders + order_outbox → commit
  ├─ afterCommit → orders.created.total + 1
  └─ HTTP 201

OrderOutboxPublisher
  └─ отдельная транзакция → блокировка строки outbox
                              → отправка в orders.created → ack
                              → published_at → commit
```

- `OrderService` сохраняет заказ и снимок события в одной транзакции. Успешный коммит оставляет запись для доставки и запускает инкремент. При откате обе строки исчезают, а счётчик остаётся прежним.
- `OrderOutboxPublisher` проверяет очередь раз в секунду. Он блокирует одну ожидающую строку до завершения попытки и выставляет `published_at` после подтверждения Kafka. Ожидание ограничено таймаутом. При сбое запись остаётся в очереди и может быть отправлена после восстановления брокера.
- Kafka получает строковый `orderId` как ключ партиции. `eventId` хранится в outbox и повторяется при переотправке. Брокер может сохранить сообщение до потери подтверждения или до сбоя при записи `published_at`. Обработчик события должен применять его бизнес-эффект один раз по `eventId`. Этот сценарий разобран в [уроке про outbox и идемпотентность](https://dbelokursky.github.io/be-101/#/m4-lesson-05).
- Для лабы используется H2 в памяти. Перезапуск приложения очищает учебные данные. Сохранение очереди между перезапусками требует постоянного хранилища.

## Как проверить

```bash
git switch lab-10-solution
mvn test
```

Все девять проверок должны пройти. Приёмник сверяет ответ `201`, сохранённый заказ, его Kafka-ключ и payload, дельту счётчика и валидацию. Отдельные сценарии проверяют откат, успешную отправку после временного сбоя продюсера и повтор с тем же `eventId` после потерянного подтверждения. Для проверки в GitHub смотри запуск **Lab check**.
